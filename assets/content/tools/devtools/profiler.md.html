分析你的應用

edit

Profiler（分析器）頁籤可讓你視覺化 Angular 的變更檢測執行情況。 這對於確定變更檢測何時以及如何影響你的應用效能非常有用。

Profiler（分析器）頁籤可讓你開始分析當前應用或匯入先前執行的現有分析。 要開始分析你的應用，請將滑鼠懸停在 Profiler（分析器）頁籤左上角的圓圈上，然後點選 Start recording（開始錄製）。

在分析期間，Angular DevTools 會捕獲執行事件，例如變更檢測和生命週期鉤子執行。 與你的應用進行互動以觸發變更檢測，並生成 Angular DevTools 可以使用的資料。 要完成錄製，請再次點選圓圈以 Stop recording（停止錄製）。

你還可以匯入現有錄製。 在 Import recording（匯入錄製）部分瞭解此功能的更多訊息。

瞭解你的應用執行情況

錄製或匯入分析後，Angular DevTools 會顯示變更檢測週期的視覺化圖。

序列中的每個條形代表你應用中的一個變更檢測週期。 條形越高，應用在此週期中執行變更檢測的時間就越長。 選擇一個條形時，DevTools 會顯示有關它的有用訊息，包括：

  • 一個條形圖，顯示在此週期中捕獲的所有元件和指令
  • Angular 在此週期中花費在執行變更檢測上的時間。
  • 使用者體驗到的估計幀率。
  • 觸發變更檢測的源。

瞭解元件執行情況

點選變更檢測週期後顯示的條形圖會顯示有關你的應用在該特定元件或指令中執行變更檢測所花費時間的詳細檢視。

此範例顯示了 NgForOf 指令花費的總時間以及在其上呼叫的方法。

分層檢視

你還可以以類似火焰圖的檢視視覺化變更檢測執行情況。

圖中的每個區塊代表渲染樹中特定位置的螢幕元素。 例如，考慮一個變更檢測週期，其中移除了一個 LoggedOutUserComponent，並在其位置渲染了一個 LoggedInUserComponent。在這種情況下，兩個元件都將顯示在同一個塊中。

x 軸表示渲染此變更檢測週期所花費的總時間。 y 軸表示元素層級。為元素執行變更檢測需要渲染其指令和子元件。 總之，此圖視覺化了哪些元件渲染耗時最長以及時間花在哪裡。

每個區塊的顏色取決於 Angular 在其中花費的時間。 Angular DevTools 根據相對於渲染耗時最多的區塊所花費的時間來確定顏色的強度。

點選某個區塊時，你將在右側面板中看到有關它的詳細訊息。 雙擊該區塊會放大它，以便你可以更輕鬆地檢視其巢狀的子項。

除錯變更檢測和 OnPush 元件

通常，該圖會視覺化給定變更檢測幀的應用渲染所需的時間。但是，某些元件（如 OnPush 元件）僅在其輸入屬性更改時才會重新渲染。對於特定的幀，在沒有這些元件的情況下視覺化火焰圖可能很有用。

要僅視覺化變更檢測幀中經歷了變更檢測過程的元件，請選擇火焰圖上方的 Change detection（變更檢測）複選框。

此檢視突出顯示了所有經過變更檢測的元件，並將未經過的元件（例如未重新渲染的 OnPush 元件）以灰色顯示。

匯入和匯出錄製

點選已錄製的分析會話右上角的 Save Profile（儲存分析）按鈕，將其匯出為 JSON 檔案並儲存到磁碟。 稍後，透過點選 Choose file（選擇檔案）輸入框在分析器的初始檢視中匯入該檔案。
