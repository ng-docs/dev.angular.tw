Angular 中的渲染策略

edit

本指南可幫助您為 Angular 應用的不同部分選擇正確的渲染策略。

什麼是渲染策略？

渲染策略決定了您的 Angular 應用的 HTML 內容何時以及在何處生成。每種策略在初始頁面載入效能、互動性、SEO 功能和伺服器資源使用之間提供了不同的權衡。

Angular 支援三種主要的渲染策略：

  • 用戶端渲染 (CSR) - 內容完全在瀏覽器中渲染
  • 靜態站點生成 (SSG/預渲染) - 內容在建立時預先渲染
  • 伺服器端渲染 (SSR) - 內容在服務器上為路由的初始請求進行渲染

用戶端渲染 (CSR)

CSR 是 Angular 的預設設定。 JavaScript 載入後，內容完全在瀏覽器中渲染。

何時使用 CSR

✅ 適用於以下場景：

  • 互動式應用（儀表盤、管理面板）
  • 實時應用
  • 不關心 SEO 的內部工具
  • 具有複雜用戶端狀態的單頁應用

❌ 可能時，請考慮避免使用：

  • 需要 SEO 的面向公眾的內容
  • 初始載入效能至關重要的頁面

CSR 的權衡

方面 影響
SEO 差 - 在 JS 執行之前爬蟲無法看到內容
初始載入 較慢 - 必須先下載並執行 JavaScript
互動性 載入後即時可用
伺服器需求 除了一些設定外，最少
複雜性 最簡單，因為它只需最少的設定即可工作

靜態站點生成 (SSG/預渲染)

SSG 在建立時將頁面預渲染為靜態 HTML 檔案。伺服器在初始頁面載入時傳送預建立的 HTML。水合後，您的應用將完全在瀏覽器中執行，就像傳統的 SPA 一樣 - 後續的導向、路由更改和 API 呼叫都發生在用戶端，無需伺服器渲染。

何時使用 SSG

✅ 適用於以下場景：

  • 營銷頁面和著陸頁
  • 部落格文章和文件
  • 內容穩定的產品目錄
  • 不因使用者而異的內容

❌ 可能時，請考慮避免使用：

  • 使用者特定的內容
  • 頻繁變化的資料
  • 實時訊息

SSG 的權衡

方面 影響
SEO 極佳 - 立即提供完整的 HTML
初始載入 最快 - 預生成的 HTML
互動性 水合完成後
伺服器需求 服務時無（CDN 友好）
建立時間 較長 - 預先生成所有頁面
內容更新 需要重新建立和重新部署

📖 實現：請參閱 SSR 指南中的自定義建立時預渲染。

伺服器端渲染 (SSR)

SSR 為路由的初始請求在服務器上生成 HTML，提供具有良好 SEO 的動態內容。伺服器渲染 HTML 並將其傳送到用戶端。

用戶端渲染頁面後，Angular 會水合應用，然後應用將完全在瀏覽器中執行，就像傳統的 SPA 一樣 - 後續的導向、路由更改和 API 呼叫都發生在用戶端，無需額外的伺服器渲染。

何時使用 SSR

✅ 適用於以下場景：

  • 電子商務產品頁面（動態定價/函式庫存）
  • 新聞網站和社交媒體信息流
  • 個性化內容，頻繁變化

❌ 可能時，請考慮避免使用：

  • 靜態內容（請改用 SSG）
  • 當服務器成本是顧慮時

SSR 的權衡

方面 影響
SEO 優秀 - 為爬蟲提供完整的 HTML
初始載入 快速 - 內容即時可見
互動性 延遲到水合完成
伺服器需求 需要伺服器
個性化 完全訪問使用者上下文
伺服器成本 更高 - 在路由的初始請求時渲染

📖 實現：請參閱 SSR 指南中的 伺服器路由 和 編寫伺服器相容元件。

選擇正確的策略

決策矩陣

如果你需要... 使用此策略 原因
SEO + 靜態內容 SSG 預渲染的 HTML，最快的載入速度
SEO + 動態內容 SSR 路由初始請求時的最新內容
無 SEO + 互動性 CSR 最簡單，無需伺服器
混合需求 混合 每個路由使用不同的策略

透過水合使 SSR/SSG 具有互動性

使用 SSR 或 SSG 時，Angular 會『水合』伺服器渲染的 HTML 以使其具有互動性。

可用策略：

  • 完全水合 - 整個應用一次性變得可互動（預設）
  • 增量水合 - 部分內容按需變得可互動（效能更佳）
  • 事件重放 - 在水合完成前捕獲點選事件

📖 瞭解更多：

  • 水合指南 - 完整的水合設定
  • 增量水合 - 使用 @defer 區塊的高階水合
