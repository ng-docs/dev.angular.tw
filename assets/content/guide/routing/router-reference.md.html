路由器參考

edit

以下各節重點介紹了一些核心路由器概念和術語。

路由器事件

在每次導向期間，Router 會通過 Router.events 屬性發出導向事件。 這些事件顯示在下表中。

路由器事件 詳情
NavigationStart 當導向開始時觸發。
RouteConfigLoadStart 在 Router 延遲載入路由設定之前觸發。
RouteConfigLoadEnd 在路由被延遲載入之後觸發。
RoutesRecognized 當路由器解析 URL 並且路由被識別時觸發。
GuardsCheckStart 當路由器開始路由的守衛階段時觸發。
ChildActivationStart 當路由器開始啟用路由的子路由時觸發。
ActivationStart 當路由器開始啟用路由時觸發。
GuardsCheckEnd 當路由器成功完成路由的守衛階段時觸發。
ResolveStart 當路由器開始路由的求解階段時觸發。
ResolveEnd 當路由器成功完成路由的求解階段時觸發。
ChildActivationEnd 當路由器完成啟用路由的子路由時觸發。
ActivationEnd 當路由器完成啟用路由時觸發。
NavigationEnd 當導向成功結束時觸發。
NavigationCancel 導向被取消時觸發。當路由守衛在導向期間回傳 false，或者透過回傳 UrlTree 或 RedirectCommand 進行重導向時，可能會發生這種情況。
NavigationError 當導向由於意外錯誤而失敗時觸發。
Scroll 表示一個捲動事件。

當你啟用 withDebugTracing 屬性時，Angular 會將這些事件記錄到控制台。

路由器術語

以下是關鍵的 Router 術語及其含義：

路由器部件 詳情
Router 顯示活動 URL 的應用元件。管理從一個元件到下一個元件的導向。
provideRouter 為瀏覽應用檢視提供必要的提供者。
RouterModule 一個單獨的 NgModule，它為瀏覽應用檢視提供必要的提供者和指令。
Routes 定義一個 Routes 陣列，每個條目都將 URL 路徑對映到一個元件。
Route 定義路由器應如何基於 URL 模式導向到元件。大多數路由由路徑和元件類別型組成。
RouterOutlet 該指令 (<router-outlet>) 標記了路由器顯示檢視的位置。
RouterLink 用於將可點選的 HTML 元素繫結到路由的指令。單擊帶有 routerLink 指令的元素（該指令繫結到字串或連結引數陣列）會觸發導向。
RouterLinkActive 當元素上或內部包含的關聯 routerLink 變為活動/非活動狀態時，用於從 HTML 元素新增/刪除類別的指令。它還可以為活動連結設定 aria-current 以獲得更好的無障礙功能。
ActivatedRoute 提供給每個路由元件的服務，其中包含特定於路由的訊息，例如路由引數、靜態資料、求解資料、全域查詢引數和全域片段。
RouterState 路由器的當前狀態，包括當前啟用路由的樹，以及用於遍歷路由樹的便捷方法。
連結引數陣列 路由解釋為路由指令的陣列。您可以將該陣列繫結到 RouterLink 或將該陣列作為引數傳遞給 Router.navigate 方法。
路由元件 一個帶有 RouterOutlet 的 Angular 元件，它根據路由導向顯示檢視。

<base href>

路由使用瀏覽器的 history.pushState 進行導向。 pushState 允許你自定義應用內 URL 路徑；例如，localhost:4200/crisis-center。 應用內 URL 可能與伺服器 URL 無法區分。

現代 HTML5 瀏覽器率先支援 pushState，這就是為什麼許多人將這些 URL 稱為『HTML5 風格』URL 的原因。

有幫助： HTML5 風格導向是路由器的預設設定。 在『位置策略和瀏覽器 URL 樣式』部分，瞭解為什麼 HTML5 風格是首選，如何調整其行為，以及如何在必要時切換到舊的雜湊（#）風格。

必須將一個 <base href> 元素新增到應用程式的 index.html 中，pushState 路由才能正常工作。 瀏覽器在引用 CSS 檔案、指令碼和影象時，使用 <base href> 值來為相對 URL 新增字首。

在 <head> 標籤之後立即新增 <base> 元素。 如果 app 資料夾是應用程式的根目錄（如本應用程式所示），請在 index.html 中設定 href 值，如下所示。

src/index.html (base-href)

<!DOCTYPE html><html lang="en">  <head>    <!-- Set the base href -->    <base href="/">    <title>Angular Router</title>    <meta charset="UTF-8">    <meta name="viewport" content="width=device-width, initial-scale=1">  </head>  <body>    <app-root></app-root>  </body></html>

HTML5 URL 和 <base href>

接下來的指南將引用 URL 的不同部分。 此圖概述了這些部分指的是什麼：

foo://example.com:8042/over/there?name=ferret#nose\_/   \______________/\_________/ \_________/ \__/ |           |            |            |        |scheme    authority      path        query   fragment

雖然路由器預設使用 HTML5 pushState 風格，但你必須使用 <base href> 來設定該策略。

設定該策略的首選方法是在 index.html 的 <head> 中新增一個 <base href> 元素標籤。

<base href="/">

沒有該標記，瀏覽器在『深度連結』到應用時可能無法載入資源（圖片、CSS、指令碼）。

有些開發者可能無法新增 <base> 元素，可能是因為他們無法訪問 <head> 或 index.html。

這些開發者仍然可以透過執行以下兩個步驟來使用 HTML5 URL：

  1. 為路由器提供一個合適的 APP_BASE_HREF 值。

  2. 對所有 Web 資源：CSS、圖片、指令碼和樣板 HTML 檔案使用根 URL（帶有 authority 的 URL）。

    • <base href> 的 path 應該以『/』結尾，因為瀏覽器會忽略路徑中緊跟最右邊『/』的字元。

    • 如果 <base href> 包含一個 query 部分，那麼只有當頁面中連結的 path 為空且沒有 query 時，才會使用該 query。 這意味著 <base href> 中的 query 僅在使用 HashLocationStrategy 時包含在內。

    • 如果頁面中的連結是根 URL（具有 authority），則不使用 <base href>。 這樣，具有 authority 的 APP_BASE_HREF 會導致 Angular 建立的所有連結忽略 <base href> 值。

    • <base href> 中的片段永遠不會被持久化

有關 <base href> 如何用於構造目標 URI 的更完整訊息，請參閱 RFC 中關於轉換引用的部分。

HashLocationStrategy

透過在 AppModule 的 RouterModule.forRoot() 的第二個引數中提供一個物件，其中包含 useHash: true 來使用 HashLocationStrategy。

providers: [  provideRouter(appRoutes, withHashLocation())]

使用 RouterModule.forRoot 時，這將在第二個引數中設定為 useHash: true：RouterModule.forRoot(routes, {useHash: true})。
