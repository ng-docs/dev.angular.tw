為其他測試環境新增元件測試工具支援

edit

開始之前

提示： 本指南假定你已閱讀過元件測試工具概覽指南。如果你是元件測試工具的新手，請先閱讀該指南。

什麼時候為測試環境新增支援才有意義？

要在以下環境中使用元件測試工具，你可以使用 Angular CDK 的兩個內建環境：

  • 單元測試
  • WebDriver 端到端測試

要使用受支援的測試環境，請閱讀為你的元件建立測試工具指南。

否則，要為其他環境新增支援，你需要定義如何與 DOM 元素互動以及 DOM 互動在你的環境中如何工作。繼續閱讀以瞭解更多訊息。

CDK 安裝

元件開發工具包 (CDK) 是一組用於建立元件的行為基元。要使用元件 harnesses，請首先從 npm 安裝 @angular/cdk。您可以使用 Angular CLI 從終端執行此操作：

ng add @angular/cdk

建立 TestElement 實現

每個測試環境都必須定義一個 TestElement 實現。 TestElement 介面作為 DOM 元素的獨立於環境的表示。它使 harnesses 能夠與 DOM 元素進行互動，而無需考慮底層環境。由於某些環境不支援同步與 DOM 元素進行互動（例如 WebDriver），因此所有 TestElement 方法都是非同步的，它們回傳一個包含操作結果的 Promise。

TestElement 提供了許多與底層 DOM 互動的方法，例如 blur()、click()、getAttribute() 等。有關方法的完整清單，請參閱 TestElement API 參考頁。

TestElement 介面主要包含與 HTMLElement 類似的方法。大多數測試環境都存在類似的方法，這使得實現這些方法相當直接。但是，在實現 sendKeys 方法時，一個重要的區別是 TestKey 列舉中的鍵碼可能與測試環境中使用的鍵碼不同。環境作者應維護從 TestKey 碼到特定測試環境中使用的碼的對映。

Angular CDK 中的 UnitTestElement 和 SeleniumWebDriverElement 實現是此介面實現的良好範例。

建立 HarnessEnvironment 實現

測試作者使用 HarnessEnvironment 來建立元件 harness 實例以供測試使用。 HarnessEnvironment 是一個抽象類別，必須對其進行擴充套件以建立新環境的具體子類別。在支援新的測試環境時，請建立一個 HarnessEnvironment 子類別，為所有抽象成員新增具體實現。

HarnessEnvironment 有一個泛型型別引數：HarnessEnvironment<E>。此引數 E 代表環境的原始元素型別。例如，對於單元測試環境，此引數為 Element。

以下是必須實現的抽象方法：

方法 描述
abstract getDocumentRoot(): E 獲取環境的根元素（例如 document.body）。
abstract createTestElement(element: E): TestElement 為給定的原始元素建立 TestElement。
abstract createEnvironment(element: E): HarnessEnvironment 建立以給定原始元素為根的 HarnessEnvironment。
abstract getAllRawElements(selector: string): Promise<E[]> 獲取環境中根元素下與給定選擇器對應的所有原始元素。
abstract forceStabilize(): Promise<void> 獲取一個在 NgZone 穩定時解析的 Promise。此外，如果適用，會告知 NgZone 穩定（例如，在 fakeAsync 測試中呼叫 flush()）。
abstract waitForTasksOutsideAngular(): Promise<void> 獲取一個在 NgZone 的父區域穩定時解析的 Promise。

除了實現缺失的方法外，此類別還應提供一種讓測試作者獲取 ComponentHarness 實例的方式。您應該定義一個受保護的建構式函式，並提供一個名為 loader 的靜態方法，該方法回傳一個 HarnessLoader 實例。這允許測試作者編寫類似的程式碼：SomeHarnessEnvironment.loader().getHarness(...)。根據特定環境的需求，該類別可以提供幾個不同的靜態方法或要求傳遞引數。（例如，TestbedHarnessEnvironment 上的 loader 方法接受一個 ComponentFixture，並且該類別提供名為 documentRootLoader 和 harnessForFixture 的附加靜態方法）。

Angular CDK 中的 TestbedHarnessEnvironment 和 SeleniumWebDriverHarnessEnvironment 實現是此介面實現的良好範例。

處理自動變更檢測

為了支援 manualChangeDetection 和並行 API，您的環境應安裝一個自動變更檢測狀態的處理器。

當您的環境想要開始處理自動變更檢測狀態時，可以呼叫 handleAutoChangeDetectionStatus(handler)。處理器函式將接收一個 AutoChangeDetectionStatus，它有兩個屬性 isDisabled 和 onDetectChangesNow()。有關更多訊息，請參閱 AutoChangeDetectionStatus API 參考頁。 如果您的環境想要停止處理自動變更檢測狀態，可以呼叫 stopHandlingAutoChangeDetectionStatus()。
