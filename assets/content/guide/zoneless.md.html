不帶 ZoneJS 的 Angular (Zoneless)

edit

為什麼要使用 Zoneless？

移除 ZoneJS 依賴的主要優勢有：

  • 效能提升：ZoneJS 使用 DOM 事件和非同步任務作為應用狀態可能已更新的指示器，並隨後觸發應用同步，以便在應用的檢視上執行變更檢測。ZoneJS 無法洞察應用狀態是否真的發生了變化，因此這種同步被觸發的頻率高於必要頻率。
  • 改進的核心 Web 指標：ZoneJS 帶來了相當大的開銷，包括有效負載大小和啟動時間成本。
  • 改進的除錯體驗：ZoneJS 使程式碼除錯更加困難。使用 ZoneJS 時，堆疊跟蹤更難理解。當代碼由於在 Angular Zone 之外而中斷時，也很難理解。
  • 更好的生態系統相容性：ZoneJS 透過修補瀏覽器 API 來工作，但不會自動修補每個新的瀏覽器 API。某些 API 無法有效地修補，例如 async/await，並且必須降級才能與 ZoneJS 一起使用。有時，生態系統中的函式庫也與 ZoneJS 修補原生 API 的方式不相容。移除 ZoneJS 作為依賴項，透過消除複雜性來源、猴子補丁和持續維護，確保了更好的長期相容性。

在應用中啟用 Zoneless 

// standalone bootstrapbootstrapApplication(MyApp, {providers: [  provideZonelessChangeDetection(),]});// NgModule bootstrapplatformBrowser().bootstrapModule(AppModule);@NgModule({  providers: [provideZonelessChangeDetection()]})export class AppModule {}

移除 ZoneJS

Zoneless 應用應從建立中完全移除 ZoneJS，以減小捆綁包大小。ZoneJS 通常透過 angular.json 中的 polyfills 選項載入，包括 build 和 test 目標。從兩者中移除 zone.js 和 zone.js/testing 以便從建立中移除它。使用顯式 polyfills.ts 檔案的專案應從檔案中移除 import 'zone.js'; 和 import 'zone.js/testing';。

從建立中移除 ZoneJS 後，也不再需要 zone.js 依賴項，並且可以完全移除該套件：

npm uninstall zone.js

Zoneless 相容性的要求

Angular 依賴於來自核心 API 的通知，以確定何時執行變更檢測以及在哪些檢視上執行。 這些通知包括：

  • ChangeDetectorRef.markForCheck（由 AsyncPipe 自動呼叫）
  • ComponentRef.setInput
  • 更新在樣板中讀取的訊號
  • 繫結的宿主或樣板偵聽器回呼
  • 附著一個被上述某項標記為髒的檢視

相容 OnPush 的元件

確保元件正在使用上述正確的通知機制的一種方法是使用 ChangeDetectionStrategy.OnPush。

OnPush 變更檢測策略不是必需的，但它是應用程式元件實現無 Zone 相容性的推薦步驟。函式庫元件並非總是能夠使用 ChangeDetectionStrategy.OnPush。 當函式庫元件是可能使用 ChangeDetectionStrategy.Default 的使用者元件的宿主時，它不能使用 OnPush，因為如果子元件不相容 OnPush 並且依賴 ZoneJS 來觸發變更檢測，這將阻止子元件被重新整理。元件可以使用 Default 策略，只要它們在需要執行變更檢測時通知 Angular（呼叫 markForCheck、使用訊號、AsyncPipe 等）。 作為使用者元件的宿主意味著使用諸如 ViewContainerRef.createComponent 之類的 API，而不僅僅是宿主使用者元件的樣板的一部分（即內容投影或使用樣板引用輸入）。

移除 NgZone.onMicrotaskEmpty、NgZone.onUnstable、NgZone.isStable 或 NgZone.onStable

應用程式和函式庫需要移除對 NgZone.onMicrotaskEmpty、NgZone.onUnstable 和 NgZone.onStable 的使用。 當應用程式啟用無 Zone 變更檢測時，這些可觀察者將永遠不會發出通知。 同樣，NgZone.isStable 將始終為 true，不應將其用作程式碼執行的條件。

NgZone.onMicrotaskEmpty 和 NgZone.onStable 可觀察者最常用於等待 Angular 完成變更檢測後再執行任務。相反，如果需要等待一次變更檢測，可以用 afterNextRender 替換它們；如果存在可能跨越多個變更檢測週期的條件，則可以用 afterEveryRender 替換。在其他情況下，使用這些可觀察者是因為它們恰好很熟悉並且具有與所需內容相似的時序。可以使用更直接的 DOM API 來替代，例如當代碼需要等待特定 DOM 狀態時使用 MutationObserver（而不是透過 Angular 的渲染鉤子間接等待）。

NgZone.run 和 NgZone.runOutsideAngular 與 Zoneless 相容

NgZone.run 和 NgZone.runOutsideAngular 不需要被移除即可使程式碼與無 Zone 應用程式相容。 事實上，移除這些呼叫可能會導致仍依賴 ZoneJS 的應用程式所使用的函式庫出現效能迴歸。

用於伺服器端渲染 (SSR) 的 PendingTasks

如果您正在 Angular 中使用 SSR，您可能知道它依賴 ZoneJS 來幫助確定應用何時『穩定』並且可以序列化。如果存在應阻止序列化的非同步任務，則不使用 ZoneJS 的應用必須使用 PendingTasks 服務讓 Angular 知道這些任務。序列化將等待所有待處理任務都被移除的第一個時刻。

待處理任務的兩個最直接的用法是 run 方法：

const taskService = inject(PendingTasks);taskService.run(async () => {  const someResult = await doSomeWorkThatNeedsToBeRendered();  this.someState.set(someResult);});

對於更復雜的用例，您可以手動新增和移除待處理任務：

const taskService = inject(PendingTasks);const taskCleanup = taskService.add();try {  await doSomeWorkThatNeedsToBeRendered();} catch {  // handle error} finally {  taskCleanup();}

此外，rxjs-interop 中的 pendingUntilEvent 輔助函式可確保應用程式在可觀察者發出、完成、出錯或被取消訂閱之前保持不穩定狀態。

readonly myObservableState = someObservable.pipe(pendingUntilEvent());

框架也在內部使用此服務來防止在非同步任務完成之前進行序列化。這些任務包括但不限於正在進行的 Router 導向和未完成的 HttpClient 請求。

測試與排查

在 TestBed 中使用 Zoneless

無 Zone 提供者函式也可以與 TestBed 一起使用，以幫助確保被測元件與無 Zone 的 Angular 應用程式相容。

TestBed.configureTestingModule({  providers: [provideZonelessChangeDetection()]});const fixture = TestBed.createComponent(MyComponent);await fixture.whenStable();

為了確保測試具有與生產程式碼最相似的行為，請儘可能避免使用 fixture.detectChanges()。當 Angular 可能原本沒有計劃變更檢測時，這將強制執行變更檢測。測試應確保這些通知正在發生，並允許 Angular 處理何時同步狀態，而不是手動強制其在測試中發生。

對於現有的測試套件，使用 fixture.detectChanges() 是一種常見模式，將其轉換為 await fixture.whenStable() 可能不值得付出努力。TestBed 仍將強制要求 fixture 的元件相容 OnPush，並在發現樣板值在沒有變更通知的情況下被更新時丟擲 ExpressionChangedAfterItHasBeenCheckedError（即 fixture.componentInstance.someValue = 'newValue';）。 如果元件在生產環境中使用，應透過更新元件以使用訊號進行狀態管理或呼叫 ChangeDetectorRef.markForCheck() 來解決此問題。 如果元件僅用作測試套件裝器且從不在應用程式中使用，則可以使用 fixture.changeDetectorRef.markForCheck()。

除錯模式檢查以確保檢測到更新

Angular 還提供了一個額外的工具來幫助驗證應用程式是否以無 Zone 相容的方式更新狀態。provideCheckNoChangesConfig({exhaustive: true, interval: <milliseconds>}) 可用於定期檢查以確保沒有繫結在沒有通知的情況下被更新。如果存在一個更新的繫結，而該繫結不會被無 Zone 變更檢測重新整理，Angular 將丟擲 ExpressionChangedAfterItHasBeenCheckedError。
