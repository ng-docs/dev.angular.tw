使用資源實現非同步回應性

edit

重要：resource 是實驗性的。它已準備好供您試用，但在穩定之前可能會發生變化。

大多數訊號 API 是同步的——signal、computed、input 等。然而，應用程式通常需要處理非同步可用的資料。 Resource 為您提供了一種將非同步資料整合到應用程式的基於訊號的程式碼中的方法。

您可以使用 Resource 來執行任何型別的非同步操作，但 Resource 最常見的用例是從伺服器獲取資料。以下範例建立一個資源來獲取一些使用者資料。

建立 Resource 最簡單的方法是使用 resource 函式。

import {resource, Signal} from '@angular/core';const userId: Signal<string> = getUserId();const userResource = resource({  // Define a reactive computation.  // The params value recomputes whenever any read signals change.  params: () => ({id: userId()}),  // Define an async loader that retrieves data.  // The resource calls this function every time the `params` value changes.  loader: ({params}) => fetchUser(params),});// Create a computed signal based on the result of the resource's loader function.const firstName = computed(() => {  if (userResource.hasValue()) {    // `hasValue` serves 2 purposes:    // - It acts as type guard to strip `undefined` from the type    // - If protects against reading a throwing `value` when the resource is in error state    return userResource.value().firstName;  }  // fallback in case the resource value is `undefined` or if the resource is in error state  return undefined;});

resource函式接受一個ResourceOptions物件，該物件具有兩個主要屬性：params和loader。

params屬性定義了一個生成引數值的回應式計算。每當此計算中讀取的訊號發生更改時，資源就會生成一個新的引數值，這與computed類似。

loader屬性定義了一個ResourceLoader——一個檢索某些狀態的非同步函式。每當params計算生成新值時，資源都會呼叫載入器，並將該值傳遞給載入器。有關更多詳細訊息，請參見下面的資源載入器。

Resource有一個value訊號，其中包含載入器的結果。

資源載入器

建立資源時，您需要指定一個ResourceLoader。此載入器是一個非同步函式，它接受單個引數——一個ResourceLoaderParams物件——並回傳一個值。

ResourceLoaderParams物件包含三個屬性：params、previous和abortSignal。

屬性 描述
params 資源params計算的值。
previous 一個具有status屬性的物件，包含之前的ResourceStatus。
abortSignal 一個 AbortSignal。有關詳細訊息，請參見下文的中止請求。

如果params計算回傳undefined，則載入器函式不會執行，資源狀態將變為'idle'。

中止請求

如果資源在載入過程中params計算發生更改，則資源會中止掛起的載入操作。

您可以在ResourceLoaderParams中使用abortSignal來回應被中止的請求。例如，原生的fetch函式接受一個AbortSignal：

const userId: Signal<string> = getUserId();const userResource = resource({  params: () => ({id: userId()}),  loader: ({params, abortSignal}): Promise<User> => {    // fetch cancels any outstanding HTTP requests when the given `AbortSignal`    // indicates that the request has been aborted.    return fetch(`users/${params.id}`, {signal: abortSignal});  },});

有關使用 AbortSignal 取消請求的更多詳細訊息，請參見 MDN 上的 AbortSignal。

重新載入

你可以透過呼叫 reload 方法以程式設計方式觸發資源的 loader。

const userId: Signal<string> = getUserId();const userResource = resource({  params: () => ({id: userId()}),  loader: ({params}) => fetchUser(params),});// ...userResource.reload();

資源狀態

資源物件具有多個 Signal 屬性，用於讀取非同步載入器的狀態。

屬性 描述
value 資源的最新值；如果未收到任何值，則為 undefined。
hasValue 資源是否具有值。
error 在執行資源載入器時遇到的最新錯誤；如果未發生錯誤，則為 undefined。
isLoading 資源載入器當前是否正在執行。
status 資源的特定ResourceStatus，如下所述。

status訊號提供了一個特定的ResourceStatus，它使用字串常數來描述資源的狀態。

狀態 value() 描述
'idle' undefined 資源沒有有效的請求，並且載入器尚未執行。
'error' undefined 載入器遇到錯誤。
'loading' undefined 由於 params 值發生更改，載入器正在執行。
'reloading' 先前的值 載入器正在執行，原因是呼叫了資源的 reload 方法。
'resolved' 已求解的值 載入器已完成。
'local' 本地設定的值 資源的值已透過 .set() 或 .update() 在本地設定

你可以使用此狀態訊息有條件地顯示使用者介面元素，例如載入指示器和錯誤訊息。

使用 httpResource 進行回應式資料獲取

httpResource 是 HttpClient 的封裝器，可將請求狀態和回應作為訊號提供給您。它透過 Angular HTTP 堆疊（包括攔截器）發出 HTTP 請求。
