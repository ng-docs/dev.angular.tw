註冊回呼函式，以便在指定的階段內，每次應用程式完成渲染時調用。可用的階段有：

  • earlyRead 在此階段，在後續的 write 回呼之前從 DOM 中讀取資料，例如執行瀏覽器本身不支援的自定義佈局。如果讀取操作可以等到 write 階段之後再進行，請優先使用 read 階段。切勿在此階段向 DOM 中寫入資料。
  • write 在此階段向 DOM 中寫入資料。切勿在此階段從 DOM 中讀取資料。
  • mixedReadWrite 在此階段可以同時從 DOM 中讀取和寫入資料。如果可能的話，請將工作分配給其他階段，切勿使用此階段。
  • read 在此階段從 DOM 中讀取資料。切勿在此階段向 DOM 中寫入資料。

如果可能，您應該優先使用 read 和 write 階段，而不是 earlyRead 和 mixedReadWrite 階段，以避免效能下降。

請注意：

  • 回呼函式在每次渲染後按以下階段順序執行：
    1. earlyRead
    2. write
    3. mixedReadWrite
    4. read
  • 同一階段的回呼函式按註冊順序執行。
  • 回呼函式僅在瀏覽器平台上執行，不會在服務器上執行。

作為此規範一部分執行的第一個階段回呼函式將不接收任何引數。此規範中每個後續階段的回呼函式將接收先前執行的階段回呼函式的回傳值作為引數。這可用於協調多個階段的工作。

Angular 無法驗證或強制執行階段的正確使用，而是依賴每位開發者遵循每個值的文件指南，並仔細選擇合適的階段，必要時重構程式碼。透過這樣做，Angular 能夠更好地最小化與手動 DOM 訪問相關的效能下降，確保您的應用程式或函式庫的最終使用者獲得最佳體驗。

元件不能保證在回呼函式執行前被水合。您在直接讀取或寫入 DOM 和佈局時必須謹慎。

註冊一個回呼函式，以便在 mixedReadWrite 階段，每次應用程式完成渲染時調用。

您應該優先為回呼函式指定一個明確的階段，否則可能會導致嚴重的效能下降。

請注意，回呼函式將執行

  • 按註冊順序
  • 每次渲染一次
  • 僅在瀏覽器平台上
  • 在 mixedReadWrite 階段期間

元件不能保證在回呼函式執行前被水合。您在直接讀取或寫入 DOM 和佈局時必須謹慎。
