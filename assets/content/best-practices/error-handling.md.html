Angular 中的未處理錯誤

edit

當你的 Angular 應用執行時，你的一些程式碼可能會丟擲錯誤。如果這些錯誤未被處理，可能會導致意外行為和無回應的 UI。本指南涵蓋了 Angular 如何處理那些未被你的應用程式碼顯式捕獲的錯誤。有關在你的應用中編寫自己的錯誤處理邏輯的指導，請參考 JavaScript 和 Angular 中錯誤處理的最佳實踐。

Angular 的錯誤處理策略的一個基本原則是，錯誤應儘可能在呼叫點暴露給開發者。這種方法確保了發起操作的程式碼擁有理解錯誤、妥善處理錯誤以及決定應用狀態所需的上下文。透過使錯誤在其源頭可見，開發者可以實現針對失敗操作的、具有相關訊息以進行恢復或向最終使用者提供訊息反饋的錯誤處理。這也有助於避免『過於籠統的錯誤』的弊端，即錯誤被報告但缺乏足夠的上下文來理解其原因。

例如，考慮一個從 API 獲取使用者資料的元件。負責進行 API 呼叫的程式碼應包含錯誤處理（例如，使用 try...catch 區塊或 RxJS 中的 catchError 運算子）來管理潛在的網路問題或 API 回傳的錯誤。這使得元件能夠顯示使用者友好的錯誤訊息或重試請求，而不是讓錯誤未被處理地傳播下去。

未處理的錯誤會被報告給 ErrorHandler

Angular 會將未處理的錯誤報告給應用的根 ErrorHandler。當提供自定義 ErrorHandler 時，請在呼叫 bootstrapApplication 時將其作為 ApplicationConfig 的一部分提供。

在建立 Angular 應用時，你經常會編寫一些程式碼，這些程式碼會被框架自動呼叫。例如，當一個元件出現在範本中時，Angular 負責呼叫該組件的建構式函式和生命週期方法。當框架執行你的程式碼時，你無法合理地新增一個 try 區塊來優雅地處理錯誤。在這種情況下，Angular 會捕獲錯誤並將它們傳送到 ErrorHandler。

Angular 不會捕獲由你的程式碼直接呼叫的 API 中的錯誤。例如，如果你有一個服務，其中有一個方法會丟擲錯誤，而你在元件中呼叫了該方法，Angular 不會自動捕獲該錯誤。你需要使用 try...catch 等機制來處理它。

Angular 僅在以下情況下捕獲使用者 Promise 或可觀察者中的非同步錯誤：

  • 存在一個明確的約定，要求 Angular 等待並使用非同步操作的結果，並且
  • 當錯誤未在回傳值或狀態中呈現時。

例如，AsyncPipe 和 PendingTasks.run 會將錯誤轉發給 ErrorHandler，而 resource 則在 status 和 error 屬性中呈現錯誤。

Angular 報告給 ErrorHandler 的錯誤是意外錯誤。這些錯誤可能是無法恢復的，或者表明應用程式狀態已損壞。應用程式應儘可能在錯誤發生的地方使用 try 區塊或適當的錯誤處理運算子（如 RxJS 中的 catchError）來提供錯誤處理，而不是依賴 ErrorHandler。ErrorHandler 最常且最恰當地僅用作將潛在的致命錯誤報告給錯誤跟蹤和日誌記錄基礎設施的機制。

TestBed 預設會重新丟擲錯誤

在許多情況下，ErrorHandler 可能只記錄錯誤，並允許應用程式繼續執行。然而，在測試中，你幾乎總是希望暴露這些錯誤。Angular 的 TestBed 會重新丟擲意外錯誤，以確保框架捕獲的錯誤不會被無意中遺漏或忽略。在極少數情況下，測試可能專門旨在確保錯誤不會導致應用程式無回應或崩潰。在這些情況下，你可以透過 TestBed.configureTestingModule({rethrowApplicationErrors: false}) 來設定 TestBed，使其不重新丟擲應用錯誤。

全域錯誤監聽器

既未被應用程式碼也未被框架的應用實例捕獲的錯誤可能會到達全域範圍。如果未加以考慮，到達全域範圍的錯誤可能會產生意外後果。在非瀏覽器環境中，它們可能導致程序崩潰。在瀏覽器中，這些錯誤可能未被報告，並且網站訪問者可能會在瀏覽器控制台中看到這些錯誤。Angular 為這兩種環境提供了全域監聽器來處理這些問題。

用戶端渲染

將 provideBrowserGlobalErrorListeners() 新增到 ApplicationConfig 會將 'error' 和 'unhandledrejection' 監聽器新增到瀏覽器視窗，並將這些錯誤轉發給 ErrorHandler。Angular CLI 預設會為新應用生成此提供者。Angular 團隊建議大多數應用處理這些全域錯誤，無論是使用框架內建的監聽器還是自定義監聽器。如果你提供自定義監聽器，可以移除 provideBrowserGlobalErrorListeners。

伺服器端渲染和混合渲染

在使用 Angular with SSR 時，Angular 會自動將 'unhandledRejection' 和 'uncaughtException' 監聽器新增到伺服器程序。這些處理器可以防止伺服器崩潰，而是將捕獲的錯誤記錄到控制台。

重要提示：如果應用正在使用 Zone.js，則只新增 'unhandledRejection' 處理器。當存在 Zone.js 時，應用 Zone 內的錯誤已轉發到應用的 ErrorHandler，並且不會到達伺服器程序。
