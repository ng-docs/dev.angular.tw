Angular 編碼風格指南

edit

簡介

本指南涵蓋了 Angular 應用程式碼的一系列風格約定。這些建議並非 Angular 正常工作所必需的，而是建立了一套編碼實踐，以促進整個 Angular 生態系統的一致性。一套一致的實踐使得共享程式碼和在專案之間遷移更加容易。

本指南不涵蓋 TypeScript 或與 Angular 無關的一般編碼實踐。有關 TypeScript，請檢視Google 的 TypeScript 風格指南。

如有疑問，優先保持一致性

每當你遇到這些規則與特定檔案的風格相沖突的情況時，請優先在檔案內保持一致性。 在一個檔案中混合不同的風格約定會比偏離本指南的建議造成更多的混亂。

命名

在檔案名中使用連字元分隔單詞

在檔案名中使用連字元（-）分隔單詞。例如，名為 UserProfile 的元件的檔案名為 user-profile.ts。

為檔案的測試使用相同的名稱，並在末尾加上 .spec

對於單元測試，檔案名的末尾應為 .spec.ts。例如，UserProfile 元件的單元測試檔案的檔案名為 user-profile.spec.ts。

檔案名與內部的 TypeScript 識別符號對應

檔案名通常應描述檔案中程式碼的內容。當檔案包含一個 TypeScript 類別時，檔案名應反映該類別名。例如，包含名為 UserProfile 的元件的檔案名為 user-profile.ts。

如果檔案包含多個主要的命名識別符號，請選擇一個描述其中程式碼的共同主題的名稱。 如果檔案中的程式碼不適合通用主題或功能區域，請考慮將程式碼分解到不同的檔案中。 避免使用過於通用的檔案名，如 helpers.ts、utils.ts 或 common.ts。

為元件的 TypeScript、範本和樣式使用相同的檔案名

元件通常由一個 TypeScript 檔案、一個範本檔案和一個樣式檔案組成。這些檔案應共享相同的名稱，但具有不同的檔案副檔名。例如，一個 UserProfile 元件可以擁有 user-profile.ts、user-profile.html 和 user-profile.css 檔案。

如果一個元件有多個樣式檔案，請在名稱後附加描述該檔案特有樣式的其他單詞。例如，UserProfile 可能有樣式檔案 user-profile-settings.css 和 user-profile-subscription.css。

專案結構

所有應用程式的程式碼都放在一個名為 src 的目錄中

您所有的 Angular UI 程式碼（TypeScript、HTML 和樣式）都應放在一個名為 src 的目錄中。 與 UI 無關的程式碼，例如設定檔案或指令碼，應放在 src 目錄之外。

這使得根應用程式目錄在不同的 Angular 專案之間保持一致，並建立了 UI 程式碼與專案中其他程式碼之間的清晰分離。

在 src 內部直接命名為 main.ts 的檔案中引導（Bootstrap）您的應用程式

用於啟動或引導 Angular 應用程式的程式碼應始終放在一個名為 main.ts 的檔案中。這代表了應用程式的主要入口點。

將緊密相關的檔案的放在同一個目錄中

Angular 元件由一個 TypeScript 檔案以及可選的範本和一或多個樣式檔案組成。您應該將它們分組在同一個目錄中。

單元測試應與被測程式碼位於同一目錄中。避免將不相關的測試收集到一個單獨的 tests 目錄中。

按功能區域組織您的專案

根據應用的屬性或目錄中程式碼的通用主題來組織專案到子目錄中。例如，電影院網站 MovieReel 的專案結構可能如下所示：

src/├─ movie-reel/│ ├─ show-times/│ │ ├─ film-calendar/│ │ ├─ film-details/│ ├─ reserve-tickets/│ │ ├─ payment-info/│ │ ├─ purchase-confirmation/

避免根據程式碼所在的目錄型別來建立子目錄。例如，避免建立像 components、directives 和 services 這樣的目錄。

避免將過多檔案放入一個目錄中，使其難以閱讀或導向。隨著目錄中文件數量的增長，考慮進一步拆分到額外的子目錄中。

每個檔案一個概念

傾向於將源檔案集中於單個概念。對於 Angular 類別來說，這通常意味著每個檔案包含一個元件、指令或服務。但是，如果你的類別相對較小並且它們作為單個概念的一部分聯絡在一起，那麼一個檔案包含多個元件或指令也是可以的。

如有疑問，請選擇能產生更小檔案的方案。

依賴注入

優先使用 inject 函式而非建構式函式引數注入

優先使用 inject 函式而非注入建構式函式引數。inject 函式的工作方式與建構式函式引數注入相同，但提供了幾個樣式上的優勢：

  • inject 通常更具可讀性，尤其是在一個類別注入了許多依賴項時。
  • 在注入的依賴項中新增註解在語法上更直接
  • inject 提供了更好的型別推斷。
  • 當使用 useDefineForClassFields 目標為 ES2022+ 時，在讀取注入依賴項的欄位時，可以避免欄位宣告和初始化的分離。

您可以使用自動工具將現有程式碼重構為 inject。

元件和指令

選擇元件選擇器

請參閱 元件指南以瞭解選擇元件選擇器的詳細訊息。

命名元件和指令成員

請參閱元件指南以瞭解有關 命名輸入屬性 和 命名輸出屬性 的詳細訊息。

選擇指令選擇器

指令應使用與您的元件相同的 特定於應用的 prefix。

當為指令使用屬性選擇器時，請使用 camelCase 屬性名稱。例如，如果您的應用程式名為『MovieReel』，並且您建立了一個向元素新增工具提示的指令，則可以使用選擇器 [mrTooltip]。

在方法之前對 Angular 特定的屬性進行分組

元件和指令應將 Angular 特定的屬性分組在一起，通常在類別宣告的頂部附近。這包括注入的依賴項、輸入、輸出和查詢。在類別的這些方法和其他屬性之前定義它們。

這種做法使得查詢類別的範本 API 和依賴項更加容易。

保持元件和指令專注於表示

元件和指令中的程式碼通常應與頁面上顯示的 UI 相關。對於有意義的、與 UI 分離的程式碼，請優先重構到其他檔案中。例如，可以將表單驗證規則或資料轉換分解到單獨的函式或類別中。

避免在範本中使用過於複雜的邏輯

Angular 範本旨在支援類似 JavaScript 的表示式。您應該利用這些表示式將相對直接的邏輯直接包含在範本表示式中。

但是，當範本中的程式碼變得過於複雜時，請將邏輯重構到 TypeScript 程式碼中（通常使用計算訊號）。

對於什麼構成『複雜』，沒有一成不變的規則。請自行判斷。

對於僅被元件範本使用的類別成員，請使用 protected。

元件類別的公共成員本身就定義了一個可以透過依賴注入和查詢訪問的公共 API。對於旨在從元件範本讀取的任何成員，請優先使用 protected 訪問。

@Component({  ...,  template: `<p>{{ fullName() }}</p>`,})export class UserProfile {  firstName = input();  lastName = input();// `fullName` is not part of the component's public API, but is used in the template.  protected fullName = computed(() => `${this.firstName()} ${this.lastName()}`);}

對於不應更改的屬性，請使用 readonly。

將由 Angular 初始化（例如透過input、model、output 和查詢）的元件和指令屬性標記為 readonly。readonly 訪問修飾符可確保由 Angular 設定的值不會被覆蓋。

@Component({/* ... */})export class UserProfile {  readonly userId = input();  readonly userSaved = output();  readonly userName = model();}

對於使用基於裝飾器的@Input、@Output 和查詢 API 的元件和指令，此建議適用於輸出屬性和查詢，但不適用於輸入屬性。

@Component({/* ... */})export class UserProfile {  @Output() readonly userSaved = new EventEmitter<void>();  @ViewChildren(PaymentMethod) readonly paymentMethods?: QueryList<PaymentMethod>;}

優先使用 class 和 style 而非 ngClass 和 ngStyle

優先使用 class 和 style 繫結，而不是使用 NgClass 和 NgStyle 指令。

<!-- PREFER --><div [class.admin]="isAdmin" [class.dense]="density === 'high'"><!-- OR --><div [class]="{admin: isAdmin, dense: density === 'high'}"><!-- AVOID --><div [ngClass]="{admin: isAdmin, dense: density === 'high'}">

class 和 style 繫結都使用了更直接的語法，與標準 HTML 屬性非常相似。這使得您的範本更易於閱讀和理解，特別是對於熟悉基本 HTML 的開發人員而言。

此外，與內建的 class 和 style 綁定語法相比，NgClass 和 NgStyle 指令會產生額外的效能開銷。

有關更多詳細訊息，請參閱繫結指南。

為事件處理程式命名時，請說明它們執行的操作，而不是觸發事件的名稱。

優先為事件處理程式命名以說明其執行的操作，而不是以觸發事件命名：

<!-- PREFER --><button (click)="saveUserData()">Save</button><!-- AVOID --><button (click)="handleClick()">Save</button>

使用有意義的名稱，可以更容易地從範本中瞭解事件的作用。

對於鍵盤事件，您可以使用 Angular 的按鍵事件修飾符和特定的處理程式名稱：

<textarea (keydown.control.enter)="commitNotes()" (keydown.control.space)="showSuggestions()">

有時，事件處理邏輯會特別長或複雜，導致無法宣告一個命名良好的單個處理程式。在這種情況下，可以回退到像 'handleKeydown' 這樣的名稱，然後根據事件詳細訊息委託給更具體的行為：

@Component({/* ... */})class RichText {  handleKeydown(event: KeyboardEvent) {    if (event.ctrlKey) {      if (event.key === 'B') {        this.activateBold();      } else if (event.key === 'I') {        this.activateItalic();      }// ...    }  }}

保持生命週期方法簡單

避免在像 ngOnInit 這樣的生命週期鉤子中放入冗長或複雜的邏輯。相反，請優先建立命名良好的方法來包含該邏輯，然後在生命週期鉤子中呼叫這些方法。生命週期鉤子名稱描述了它們何時執行，這意味著其中的程式碼沒有描述其功能的有意義的名稱。

// PREFERngOnInit() {  this.startLogging();  this.runBackgroundTask();}// AVOIDngOnInit() {  this.logger.setMode('info');  this.logger.monitorErrors();  // ...and all the rest of the code that would be unrolled from these methods.}
