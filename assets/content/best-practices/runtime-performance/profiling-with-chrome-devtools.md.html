使用 Chrome DevTools 進行效能分析

edit

Angular 與 Chrome DevTools 可擴充套件性 API 整合，可直接在 Chrome DevTools 效能面板 中展示框架特定的資料和見解。

啟用整合後，您可以 記錄一個效能設定檔案，其中包含兩組資料：

  • 基於 Chrome 對您在瀏覽器中執行的程式碼的理解的標準效能條目，以及
  • 由框架執行時貢獻的 Angular 特定條目。

兩組資料一起顯示在同一個頁籤上，但位於不同的軌道上：

Angular 特定的資料以框架概念（元件、變更檢測、生命週期鉤子等）來表達，並伴隨著瀏覽器捕獲的低階函式和方法呼叫。這兩組資料是相關的，您可以切換不同的檢視和詳細程度。

您可以使用 Angular 軌道更好地瞭解您的程式碼在瀏覽器中的執行方式，包括：

  • 確定給定的程式碼區塊是否是 Angular 應用的一部分，或者它是否屬於在同一頁面上執行的另一個指令碼。
  • 識別效能瓶頸並將它們歸因於特定的元件或服務。
  • 透過對每個變更檢測週期進行視覺化分解，深入瞭解 Angular 的內部工作原理。

記錄設定檔案

啟用整合

您可以透過以下兩種方式之一啟用 Angular 效能分析：

  1. 在 Chrome 的控制台面板中執行 ng.enableProfiling()，或者
  2. 在您的應用程式啟動程式碼中包含對 enableProfiling() 的呼叫（從 @angular/core 匯入）。

注意： Angular 效能分析僅在開發模式下工作。

以下是如何在應用程式引導中啟用整合以捕獲所有可能事件的範例：

import { enableProfiling } from '@angular/core';import { bootstrapApplication } from '@angular/platform-browser';import { MyApp } from './my-app';// Turn on profiling *before* bootstrapping your application// in order to capture all of the code run on start-up.enableProfiling();bootstrapApplication(MyApp);

解釋記錄的設定檔案

您可以使用『Angular』自定義軌道來快速識別和診斷效能問題。以下各節描述了一些常見的效能分析場景。

區分您的 Angular 應用與其他在同一頁面上的任務

由於 Angular 和 Chrome 資料顯示在分開但相關的軌道上，您可以看到 Angular 的應用程式碼何時執行，以及與其他瀏覽器處理（通常是佈局和繪製）或在同一頁面上執行的其他指令碼（在這種情況下，自定義 Angular 軌道沒有任何資料）的執行情況：

這使您能夠確定後續調查應側重於 Angular 應用程式碼還是您程式碼庫的其他部分或依賴項。

顏色編碼

Angular 在火焰圖中使用顏色來區分任務型別：

  • 🟦 藍色代表應用程式開發人員編寫的 TypeScript 程式碼（例如：服務、元件建構式函式和生命週期鉤子等）。
  • 🟪 紫色代表應用程式開發人員編寫並由 Angular 編譯器轉換的樣板程式碼。
  • 🟩 綠色代表應用程式程式碼的入口點並標識執行程式碼的原因。

以下範例在各種實際錄製中說明瞭所描述的顏色編碼。

範例：應用程式引導

應用程式引導過程通常包括：

  • 以藍色標記的觸發器，例如對 bootstrapApplication 的呼叫、根元件的實例化以及初始變更檢測
  • 引導過程中實例化的各種 DI 服務，以綠色標記。

範例：元件執行

一個元件處理通常表示為一個入口點（藍色），然後是其樣板執行（紫色）。樣板反過來可能會觸發指令的實例化和生命週期鉤子的執行（綠色）：

範例：變更檢測

變更檢測週期通常由一個或多個資料同步傳遞（藍色）組成，每次傳遞遍歷一部分元件。

透過這種資料視覺化，可以立即識別參與變更檢測的元件以及被跳過的元件（通常是未標記為髒的 OnPush 元件）。

此外，您可以檢查一次變更檢測的同步傳遞次數。超過一次同步傳遞表明狀態在變更檢測期間被更新。您應該避免這種情況，因為它會減慢頁面更新速度，在最壞的情況下甚至可能導致無限迴圈。
