Angular Signal 的 RxJS 互操作

edit

@angular/core/rxjs-interop 套件提供了幫助您整合 RxJS 和 Angular Signals 的 API。

使用 toSignal 從 RxJs 可觀察者建立一個 Signal

使用 toSignal 函式來建立一個跟蹤 Observable 值的 Signal。它的行為類似於樣板中的 async pipe，但更靈活，並且可以在應用程式的任何地方使用。

import { Component } from '@angular/core';import { AsyncPipe } from '@angular/common';import { interval } from 'rxjs';import { toSignal } from '@angular/core/rxjs-interop';@Component({  template: `{{ counter() }}`,})export class Ticker {  counterObservable = interval(1000);  // Get a `Signal` representing the `counterObservable`'s value.  counter = toSignal(this.counterObservable, {initialValue: 0});}

與 async pipe 類似，toSignal 會立即訂閱 Observable，這可能會觸發副作用。當呼叫 toSignal 的元件或服務被銷燬時，由 toSignal 建立的訂閱會自動從給定的 Observable 中取消訂閱。

重要提示： toSignal 會建立一個訂閱。您應該避免對同一個 Observable 重複呼叫它，而是複用它回傳的 Signal。

注入上下文

toSignal 預設需要在注入上下文中執行，例如在元件或服務的構造期間。如果注入上下文不可用，您可以手動指定要使用的Injector。

初始值

Observable 在訂閱時可能不會同步產生值，但 Signal 始終需要一個當前值。有幾種方法可以處理 toSignal Signal 的『初始』值。

initialValue 選項

如上面的範例所示，你可以使用 initialValue 選項指定 signal 在 Observable 首次發出之前應回傳的值。

undefined 初始值

如果你不提供 initialValue，則生成的 signal 將回傳 undefined，直到 Observable 發出值。這類似於 async 通道回傳 null 的行為。

requireSync 選項

某些 Observable 保證同步發出值，例如 BehaviorSubject。在這些情況下，你可以指定 requireSync: true 選項。

當 requiredSync 為 true 時，toSignal 會強制 Observable 在訂閱時同步發出值。這保證了 Signal 始終有一個值，並且不需要 undefined 型別或初始值。

manualCleanup

預設情況下，當建立它的元件或服務被銷燬時，toSignal 會自動從 Observable 中取消訂閱。

要覆蓋此行為，你可以傳遞 manualCleanup 選項。你可以將此設定用於那些自然完成的 Observable。

錯誤和完成

如果在 toSignal 中使用的 Observable 產生錯誤，則在讀取 Signal 時會丟擲該錯誤。

如果在 toSignal 中使用的 Observable 完成，則 Signal 會繼續回傳完成之前的最新發出值。

使用 toObservable 從 Signal 建立一個 RxJS 可觀察者

使用 toObservable 工具來建立一個跟蹤 Signal 值的 Observable。Signal 的值透過一個 effect 進行監控，該 effect 在值更改時將其發出到 Observable。

import { Component, signal } from '@angular/core';import { toObservable } from '@angular/core/rxjs-interop';@Component(/* ... */)export class SearchResults {  query: Signal<string> = inject(QueryService).query;  query$ = toObservable(this.query);  results$ = this.query$.pipe(    switchMap(query => this.http.get('/search?q=' + query ))  );}

隨著 query Signal 的變化，query$ Observable 會發出最新的查詢並觸發新的 HTTP 請求。

注入上下文

toObservable 預設需要在注入上下文中執行，例如在元件或服務的構造期間。如果注入上下文不可用，您可以手動指定要使用的Injector。

toObservable 的時序

toObservable 使用 effect 在 ReplaySubject 中跟蹤 Signal 的值。訂閱時，第一個值（如果可用）可能會同步發出，所有後續值將是非同步的。

與 Observable 不同，Signal 從不提供同步的更改通知。即使您多次更新 Signal 的值，toObservable 也只會在 Signal 穩定後發出該值。

const obs$ = toObservable(mySignal);obs$.subscribe(value => console.log(value));mySignal.set(1);mySignal.set(2);mySignal.set(3);

在這裡，只會記錄最後一個值 (3)。

使用 rxResource 處理非同步資料

重要提示： rxResource 處於實驗階段。您可以嘗試使用它，但在穩定之前可能會發生更改。

Angular 的 resource 函式為您提供了一種將非同步資料整合到應用程式基於 Signal 的程式碼中的方法。在此模式的基礎上，rxResource 允許您定義一個資源，該資源的來源是根據 RxJS Observable 定義的。rxResource 不接受 loader 函式，而是接受一個接受 RxJS Observable 的 stream 函式。

import {Component, inject} from '@angular/core';import {rxResource} from '@angular/core/rxjs-interop';@Component(/* ... */)export class UserProfile {  // This component relies on a service that exposes data through an RxJS Observable.  private userData = inject(MyUserDataClient);  protected userId = input<string>();  private userResource = rxResource({    params: () => this.userId(),    // The `stream` property expects a factory function that returns    // a data stream as an RxJS Observable.    stream: ({params}) => this.userData.load(params.userId),  });}

stream 屬性接受一個 RxJS Observable 的工廠函式。此工廠函式會接收資源的 params 值並回傳一個 Observable。每次 params 計算產生新值時，資源都會呼叫此工廠函式。有關傳遞給工廠函式的引數的更多詳細訊息，請參閱資源載入器。

在其他所有方面，rxResource 的行為與 resource 相同，並提供相同的 API 來指定引數、讀取值、檢查載入狀態和檢查錯誤。
