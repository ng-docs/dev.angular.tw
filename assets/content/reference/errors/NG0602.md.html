在回應式上下文中不允許的函式呼叫

edit

一個不允許在回應式上下文中執行的函式，卻從回應式上下文中被呼叫。

例如，不能在 computed 或正在執行的 effect 中排程一個 effect。 避免將 effect 等函式作為範本表示式的一部分進行呼叫，因為這些表示式會在它們自己的回應式上下文中執行。

計算表示式應為純粹的。 純粹意味著表示式不會觸發任何副作用。 副作用是諸如排程 afterNextRender/afterEveryRender、建立新的 effect 或訂閱可觀察者等操作。

為了避免常見的陷阱，某些操作在回應式上下文中被明確禁止。 例如，在 computed 中使用 afterNextRender/afterEveryRender 會在每次計算表示式求值時調度新的渲染鉤子。 這很可能不是預期的，並且可能會降低應用程式效能。

修復此錯誤

本錯誤指南並非詳盡無遺。 它捕獲了一些常見場景以及如何解決此錯誤。

afterNextRender/afterEveryRender

將 afterNextRender/afterEveryRender 的呼叫移出回應式上下文。

排程渲染後鉤子的一個好地方是在元件的類別建構式函式中。 或者，使用 untracked 來離開回應式上下文並顯式選擇退出此錯誤。

effect

將 effect 的呼叫移出回應式上下文。

排程 effect 的一個好地方是在 @Component 的類別建構式函式中。

toSignal

將 toSignal 的呼叫移出回應式上下文。

result = computed(() => {  const dataSignal = toSignal(dataObservable$);  return doSomething(dataSignal());});

可以重構為：

dataSignal = toSignal(dataObservable$);result = computed(() => doSomething(dataSignal()));

或者，如果這不可行，請考慮手動訂閱可觀察者。

作為最後的手段，使用 untracked 來離開回應式上下文。 請注意，離開回應式上下文可能導致 untracked 內部的訊號讀取被忽略。

@debugging

錯誤訊息提到了意外呼叫的函式。 在你的應用程式碼中查詢此函式呼叫。

或者，瀏覽器中的堆疊跟蹤將顯示函式在何處被呼叫以及它位於何處。
