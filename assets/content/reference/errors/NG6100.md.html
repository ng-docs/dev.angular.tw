NgModule.id 設定為 module.id 反模式

edit

將 module.id 用作 NgModule 的 id 是一種常見的反模式，並且可能在你的程式碼中沒有實際用途。

可以使用 id 宣告 NgModule：

@NgModule({  id: 'my_module'})export class MyModule {}

宣告一個 id 會使該 NgModule 可透過 getNgModuleById() 操作進行查詢。此功能很少使用，主要是在非常特定的捆綁場景中，用於延遲載入 NgModules 而不獲取它們的直接引用。在大多數 Angular 程式碼中，應改用 ES 動態 import() (import('./path/to/module'))，因為它提供了對正在載入的 NgModule 的直接引用，而無需全域註冊的副作用。

如果您不使用 getNgModuleById，則無需為您的 NgModules 提供 id。提供一個 id 有一個顯著的缺點：它會使 NgModule 無法進行搖樹最佳化，這會影響您的捆綁包大小。

特別是，指定 id: module.id 的模式源於對 @NgModule.id 的誤解。在早期版本的 Angular 中，有時需要在 @Component 元資料中包含 moduleId: module.id 屬性。

將 module.id 用於 @NgModule.id 可能是由於混淆了 @Component.moduleId 和 @NgModule.id。module.id 對於 getNgModuleById() 操作通常沒有用，因為 id 需要是一個眾所周知的字串，而 module.id 對消費者來說通常是不透明的。

除錯錯誤

你可以從你的 NgModules 中刪除 id: module.id 宣告。編譯器會忽略此宣告，並改為發出此警告。
