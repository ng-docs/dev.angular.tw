使用 Resources API 和訊號管理非同步資料

edit

既然您已經學會了如何使用連結訊號派生狀態，那麼讓我們來探索如何使用 Resource API 處理非同步資料。Resource API 提供了一種使用訊號管理非同步操作的強大方法，內建了載入狀態、錯誤處理和請求管理。

在此活動中，您將學習如何使用 resource() 函式非同步載入資料，以及如何透過建立一個示範 Resource API 實際應用的使用者設定檔案載入器來處理非同步操作的不同狀態。

  1. 匯入 resource 函式和 API

    將 resource 新增到現有匯入中，並匯入假的 API 函式。

    // Add resource to existing importsimport {Component, signal, computed, resource, ChangeDetectionStrategy} from '@angular/core';// Import mock API functionimport {loadUser} from './user-api';

  2. 為使用者資料建立資源

    在元件類別中新增一個屬性，該屬性建立一個資源，用於根據使用者 ID 訊號載入使用者資料。

    userId = signal(1);userResource = resource({  params: () => ({ id: this.userId() }),  loader: (params) => loadUser(params.params.id)});

  3. 新增方法與資源進行互動

    新增方法來更改使用者 ID 和重新載入資源。

    loadUser(id: number) {  this.userId.set(id);}reloadUser() {  this.userResource.reload();}

    更改 params 訊號會自動觸發重新載入，或者您可以使用 reload() 手動重新載入。

  4. 為資源狀態建立計算訊號

    新增計算訊號以訪問資源的各種狀態。

    isLoading = computed(() => this.userResource.status() === 'loading');hasError = computed(() => this.userResource.status() === 'error');

    資源提供一個可以為 'loading'、'success' 或 'error' 的 status() 訊號，一個用於載入資料的 value() 訊號，以及一個安全檢查資料是否可用的 hasValue() 方法。

  5. 連線按鈕並顯示資源狀態

    樣板結構已提供。現在連線所有內容：

    第一部分。為按鈕新增點選處理程式：

    <button (click)="loadUser(1)">Load User 1</button><button (click)="loadUser(2)">Load User 2</button><button (click)="loadUser(999)">Load Invalid User</button><button (click)="reloadUser()">Reload</button>

    第二部分。用資源狀態處理替換佔位符：

    @if (isLoading()) {  <p>Loading user...</p>} @else if (hasError()) {  <p class="error">Error: {{ userResource.error()?.message }}</p>} @else if (userResource.hasValue()) {  <div class="user-info">    <h3>{{ userResource.value().name }}</h3>    <p>{{ userResource.value().email }}</p>  </div>}

    資源提供了不同的方法來檢查其狀態：

    • isLoading() - 獲取資料時為 true
    • hasError() - 發生錯誤時為 true
    • userResource.hasValue() - 資料可用時為 true
    • userResource.value() - 訪問載入的資料
    • userResource.error() - 訪問錯誤訊息

太棒了！您現在已經學會瞭如何將 Resource API 與訊號一起使用。需要記住的關鍵概念：

  • 資源是回應式的：當引數更改時，它們會自動重新載入
  • 內建狀態管理：資源提供 status()、value() 和 error() 訊號
  • 自動清理：資源會自動處理請求取消和清理
  • 手動控制：您可以根據需要手動重新載入或中止請求
