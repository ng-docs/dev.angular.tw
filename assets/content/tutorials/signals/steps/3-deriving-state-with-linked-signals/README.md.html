使用連結訊號派生狀態

edit

既然您已經學習了如何使用 computed 訊號派生狀態，您已經為 notificationsEnabled 建立了一個 computed 訊號，該訊號會自動跟蹤您的使用者狀態。但是，如果使用者希望在線上時手動停用通知，該怎麼辦？這時就需要用到連結訊號了。

連結訊號是可寫訊號，它們與其源訊號保持回應式連線。它們非常適合建立通常遵循計算但可在需要時被覆蓋的狀態。

在此活動中，您將透過將先前使用者狀態系統的 computed notificationsEnabled 增強為可寫的連結訊號，來學習 linkedSignal() 與 computed() 的區別。

  1. 匯入 linkedSignal 函式

    將 linkedSignal 新增到您現有的匯入中。

    // Add linkedSignal to existing importsimport {Component, signal, computed, linkedSignal, ChangeDetectionStrategy} from '@angular/core';

  2. 使用相同的表示式將 computed 轉換為 linkedSignal

    使用完全相同的表示式，將 computed notificationsEnabled 替換為 linkedSignal：

    // Previously (from lesson 2):// notificationsEnabled = computed(() => this.userStatus() === 'online');// Now with linkedSignal - same expression, but writable:notificationsEnabled = linkedSignal(() => this.userStatus() === 'online');

    表示式是相同的，但 linkedSignal 建立了一個可寫訊號。當 userStatus 更改時，它仍會自動更新，但您也可以手動設定它。

  3. 新增一個手動切換通知的方法

    新增一個方法來示範連結訊號可以直接寫入：

    toggleNotifications() {  // This works with linkedSignal but would error with computed!  this.notificationsEnabled.set(!this.notificationsEnabled());}

    這是關鍵區別：computed 訊號是隻讀的，但連結訊號可以手動更新，同時保持其回應式連線。

  4. 更新樣板以新增手動通知控制元件

    更新您的樣板以新增一個用於通知的切換按鈕：

    <div class="status-info">  <div class="notifications">    <strong>Notifications:</strong>    @if (notificationsEnabled()) {      Enabled    } @else {      Disabled    }    <button (click)="toggleNotifications()" class="override-btn">      @if (notificationsEnabled()) {        Disable      } @else {        Enable      }    </button>  </div>  <!-- existing message and working-hours divs remain --></div>

  5. 觀察回應式行為

    現在測試該行為：

    1. 更改使用者狀態 - 注意 notificationsEnabled 如何自動更新
    2. 手動切換通知 - 它會覆蓋 computed 值
    3. 再次更改狀態 - 連結訊號與其計算重新同步

    這表明連結訊號即使在手動設定後也能保持其回應式連線！

太棒了！您已經瞭解了 computed 和 linked 訊號之間的關鍵區別：

  • Computed 訊號：只讀，始終從其他訊號派生
  • 連結訊號：可寫，既可以派生又可以手動更新
  • 何時使用 computed：值應始終被計算
  • 何時使用 linkedSignal：您需要一個可以被覆蓋的預設計算
