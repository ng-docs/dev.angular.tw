使用 effect 回應訊號變化

edit

既然你已經學會了如何使用訊號查詢來查詢子元素，現在讓我們來探索如何使用 effect 來回應訊號變化。Effect 是當其依賴項發生變化時自動執行的函式，非常適合用於日誌記錄、DOM 操作或 API 呼叫等副作用。

重要提示：Effect 應該是你最後考慮的 API。對於派生值，請始終優先使用 computed()；對於可以派生和手動設定的值，請優先使用 linkedSignal()。如果你發現自己使用 effect 將資料從一個訊號複製到另一個訊號，這表明你應該將你的事實之源（source-of-truth）移到更高層，並改用 computed() 或 linkedSignal()。Effect 最適合將訊號狀態同步到指令式、非訊號 API。

在此活動中，你將學習如何為回應訊號變化的合法副作用恰當地使用 effect() 函式。

你有一個已經設定好訊號的主題管理器應用。現在你將新增 effects 來自動回應訊號變化。

  1. 匯入 effect 函式

    將 effect 新增到你現有的匯入中。

    // Add effect to existing importsimport {Component, signal, computed, effect, ChangeDetectionStrategy} from '@angular/core';

    effect 函式建立一個回應式的副作用，當它讀取的任何訊號發生變化時，該副作用會自動執行。

  2. 為本地儲存建立一個 effect

    新增一個 effect，當主題更改時自動將其儲存到本地儲存。

    constructor() {  // Save theme to localStorage whenever it changes  effect(() => {    localStorage.setItem('theme', this.theme());    console.log('Theme saved to localStorage:', this.theme());  });}

    此 effect 在主題訊號更改時運行，自動持久化使用者的偏好設定。

  3. 建立一個用於記錄使用者活動的 effect

    新增一個 effect，在使用者登入或登出時進行記錄。

    constructor() {  // ... previous effect  // Log user activity changes  effect(() => {    const status = this.isLoggedIn() ? 'logged in' : 'logged out';    const user = this.username();    console.log(`User ${user} is ${status}`);  });}

    此 effect 展示了 effects 如何讀取多個訊號並對其中任何訊號的變化做出反應。

  4. 建立一個帶清理功能的 effect

    新增一個 effect，該 effect 設定一個計時器並在元件銷燬時進行清理。

    constructor() {  // ... previous effects  // Timer effect with cleanup  effect((onCleanup) => {    const interval = setInterval(() => {      console.log('Timer tick - Current theme:', this.theme());    }, 5000);    // Clean up the interval when the effect is destroyed    onCleanup(() => {      clearInterval(interval);      console.log('Timer cleaned up');    });  });}

    此 effect 展示了如何在 effect 被銷燬或重新執行時清理資源。

  5. 測試 effects

    開啟瀏覽器控制台並與應用進行互動：

    • 切換主題 - 檢視本地儲存的儲存和計時器日誌
    • 登入/登出 - 檢視使用者活動日誌
    • 觀察計時器 - 檢視每 5 秒一次的週期性主題日誌

    當其跟蹤的訊號發生變化時，effects 會自動執行！

太棒了！你現在已經學會瞭如何將 effects 與訊號一起使用。需要記住的關鍵概念：

  • Effects 是回應式的：當它們讀取的任何訊號發生變化時，它們會自動執行
  • 僅用於副作用：非常適合日誌記錄、DOM 操作、API 呼叫以及同步到指令式 API
  • 清理：使用 onCleanup 回呼來清理計時器或訂閱等資源
  • 自動跟蹤：Effects 會自動跟蹤它們讀取的訊號，並在這些訊號發生變化時重新執行

請記住：謹慎使用 effects！本課中的範例（localStorage 同步、日誌記錄、計時器）是恰當的用法。避免將 effects 用於：

  • 從其他訊號派生值 - 請改用 computed()
  • 建立可寫派生狀態 - 請改用 linkedSignal()
  • 在訊號之間複製資料 - 請重構以使用共享的事實之源

Effects 功能強大，但在 computed() 和 linkedSignal() 無法解決你的用例時，它們應該是你的最後選擇。
